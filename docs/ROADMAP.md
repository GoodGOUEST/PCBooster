# 路线图 / 已知问题

按优先级排序。欢迎认领，认领前请先在 issue 里说一句避免撞车。

## P1（影响可用性 / 发布门槛）

| 项 | 现状 | 目标 |
|---|---|---|
| **可选提权** | `app.manifest` 用 `highestAvailable`，标准用户每次启动都弹 UAC | 默认以普通权限启动，只对需要提权的功能（核心隔离/工作集保护/部分电源项）做按需提权引导，并在 UI 里说明降级了什么 |
| **崩溃残留标记** | 进程被强杀/崩溃后，系统可能停在"高性能 + 被改过的亲和性"状态 | 写入 `running.lock`，启动时检测上次是否异常退出，是则先还原再启动 |
| **多用户 / RDP 配置隔离** | 配置文件在 `%AppData%` 但互斥锁是会话级的 | 配置按 SID 隔离；RDP/多会话下不互相接管调度 |
| **EventBus 消费线程** | 每个事件 `Task.Run`，`OrderedLoop` 异常即退出 | 固定消费线程 + 异常隔离，避免事件风暴时线程池抖动 |
| **代码签名 + 安装包 + 自动更新 + 崩溃上报** | 均无 | 见 README 的"发布"章节 |

## P2（正确性 / 覆盖）

| 项 | 说明 |
|---|---|
| **>64 逻辑核 / 多处理器组** | 当前只处理第一组；`CpuTopologyEx` 已按 `GROUP_AFFINITY` 解析结构，需要补多组映射 |
| **混合 DPI（PerMonitorV2）** | 当前 SystemAware，跨屏拖动会发虚；切换清单后需要重建窗口才能生效 |
| **CacheManager 首屏旧值** | 首次打开面板可能显示 0.0%，需要一次强制刷新 |
| **异步内存回收** | 回收在锁内 `Sleep` + 逐进程 Trim，高负载时会拖慢心跳 |
| **`ApplyAllRules` 每进程 LINQ** | 规则多时每轮都有分配，可预排序 + 缓存 |

## 新功能（有明确设计，尚未实现）

1. **线程级「双首核」软偏好**：取游戏 CPU 时间最高的 2 个线程，用 `SetThreadIdealProcessor` 定位到两个**不同物理核**（只是偏好，绝不硬绑线程），减少搬核与 SMT 兄弟争用。
2. **三档调度强度**：`软偏好（只调优先级/理想核）` / `核心范围（亲和性掩码）` / `强绑（掩码 + 排除 SMT 兄弟）`，默认中间档。
3. **核心布局 UI**：把 CPU 拓扑（L3 域 / P-E 核）画出来，让用户点选哪些核给游戏、哪些留给后台，并保存成规则。
4. **I/O 优先级取代部分 Trim**：后台进程设 VeryLow I/O 优先级（`JobObjectApi` 已有字段），比清工作集更温和。
5. **可验证效果报告**：导入帧时间记录（PresentMon / CapFrameX CSV），自动给出改动前后的 0.1% low / 1% low 对比 —— 这是本项目"反蛇油"定位的关键功能。

## 明确不做

- 进程注入、内核驱动、图形 API hooking
- 对反作弊进程的任何写操作
- "优化注册表""禁用系统服务""清理内存"
- 全局持久改动且退出不还原的项（例如 `Win32PrioritySeparation`）
